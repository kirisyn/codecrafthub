# CodeCraftHub API – Test Guide

Every command below is ready to copy and paste. All responses shown were
captured from a real run of the server.

## Before you start

Open **two terminals** in the project folder.

Terminal 1 – start the server:

```bash
source .venv/bin/activate
flask --app app run --debug
```

Terminal 2 – run the commands below. Every write request needs the JSON
header, so define it once to keep the commands short:

```bash
BASE=http://localhost:5000
JSON='Content-Type: application/json'
```

Tip: pipe any command into `python3 -m json.tool` to pretty-print the
response, e.g. `curl -s $BASE/api/courses | python3 -m json.tool`.

To run **all** tests automatically instead: `bash tests/test_api.sh`

## Part 1 – Successful operations

### 1.1 Get all courses (empty on a fresh install)

```bash
curl -i $BASE/api/courses
```

Expected: `HTTP/1.1 200 OK`

```json
[]
```

### 1.2 Create a course – `POST /api/courses`

Payload: all four fields are required.

```bash
curl -i -X POST $BASE/api/courses -H "$JSON" -d '{
  "name": "Flask Fundamentals",
  "description": "Learn how to build REST APIs with Flask",
  "target_date": "2026-12-31",
  "status": "Not Started"
}'
```

Expected: `HTTP/1.1 201 CREATED`. Note that `id` and `created_at` were
generated by the server.

```json
{
  "created_at": "2026-10-26T15:02:34",
  "description": "Learn how to build REST APIs with Flask",
  "id": 1,
  "name": "Flask Fundamentals",
  "status": "Not Started",
  "target_date": "2026-12-31"
}
```

### 1.3 Create a second course

```bash
curl -i -X POST $BASE/api/courses -H "$JSON" -d '{
  "name": "Docker for Developers",
  "description": "Containerize Python applications",
  "target_date": "2027-03-15",
  "status": "In Progress"
}'
```

Expected: `201 CREATED` with `"id": 2`.

### 1.4 Get all courses again

```bash
curl -i $BASE/api/courses
```

Expected: `200 OK` with a list containing both courses.

```json
[
  {
    "created_at": "2026-10-26T15:02:34",
    "description": "Learn how to build REST APIs with Flask",
    "id": 1,
    "name": "Flask Fundamentals",
    "status": "Not Started",
    "target_date": "2026-12-31"
  },
  {
    "created_at": "2026-10-26T15:02:34",
    "description": "Containerize Python applications",
    "id": 2,
    "name": "Docker for Developers",
    "status": "In Progress",
    "target_date": "2027-03-15"
  }
]
```

### 1.5 Get one course – `GET /api/courses/<id>`

```bash
curl -i $BASE/api/courses/2
```

Expected: `200 OK`

```json
{
  "created_at": "2026-10-26T15:02:34",
  "description": "Containerize Python applications",
  "id": 2,
  "name": "Docker for Developers",
  "status": "In Progress",
  "target_date": "2027-03-15"
}
```

### 1.5b Get statistics – `GET /api/courses/stats`

```bash
curl -i $BASE/api/courses/stats
```

Expected: `200 OK`. With the two courses from 1.2 and 1.3:

```json
{
  "by_status": {
    "Completed": 0,
    "In Progress": 1,
    "Not Started": 1
  },
  "total": 2
}
```

Every status is always listed, even with a count of 0. On an empty
installation `total` is 0 and all three counts are 0.

### 1.6 Update a course – `PUT /api/courses/<id>`

Payload: send **only the fields you want to change**. Everything else keeps
its current value. `id` and `created_at` cannot be changed.

```bash
curl -i -X PUT $BASE/api/courses/2 -H "$JSON" -d '{"status": "In Progress"}'
```

Expected: `200 OK` with the whole updated course. Only `status` changed.

```json
{
  "created_at": "2026-10-26T15:02:34",
  "description": "Containerize Python applications",
  "id": 2,
  "name": "Docker for Developers",
  "status": "In Progress",
  "target_date": "2027-03-15"
}
```

You can change several fields in one request:

```bash
curl -i -X PUT $BASE/api/courses/2 -H "$JSON" -d '{
  "description": "Containerize Python applications - done!",
  "status": "Completed"
}'
```

Expected: `200 OK`

```json
{
  "created_at": "2026-10-26T15:02:34",
  "description": "Containerize Python applications - done!",
  "id": 2,
  "name": "Docker for Developers",
  "status": "Completed",
  "target_date": "2027-03-15"
}
```

### 1.7 Delete a course – `DELETE /api/courses/<id>`

```bash
curl -i -X DELETE $BASE/api/courses/2
```

Expected: `200 OK`

```json
{"message": "Course with id 2 deleted"}
```

Verify it is gone: `curl -i $BASE/api/courses/2` now returns `404`.

## Part 2 – Error scenarios

### 2.1 Missing required fields

```bash
curl -i -X POST $BASE/api/courses -H "$JSON" -d '{"name": "Only a name"}'
```

Expected: `400 BAD REQUEST`

```json
{"error": "Missing required field(s): description, target_date, status"}
```

### 2.2 Empty required field (an empty string counts as missing)

```bash
curl -i -X POST $BASE/api/courses -H "$JSON" -d '{
  "name": "",
  "description": "Empty name is not allowed",
  "target_date": "2026-12-31",
  "status": "Not Started"
}'
```

Expected: `400`

```json
{"error": "Missing required field(s): name"}
```

### 2.3 Invalid status value

```bash
curl -i -X POST $BASE/api/courses -H "$JSON" -d '{
  "name": "Kubernetes",
  "description": "Orchestration",
  "target_date": "2026-12-31",
  "status": "Done"
}'
```

Expected: `400`

```json
{"error": "Invalid status 'Done'. Must be one of: Not Started, In Progress, Completed"}
```

### 2.4 Wrong date format

```bash
curl -i -X POST $BASE/api/courses -H "$JSON" -d '{
  "name": "Kubernetes",
  "description": "Orchestration",
  "target_date": "31/12/2026",
  "status": "Not Started"
}'
```

Expected: `400`

```json
{"error": "'target_date' must be a valid date in YYYY-MM-DD format"}
```

### 2.5 Impossible date (right format, no such day)

```bash
curl -i -X POST $BASE/api/courses -H "$JSON" -d '{
  "name": "Kubernetes",
  "description": "Orchestration",
  "target_date": "2026-02-30",
  "status": "Not Started"
}'
```

Expected: `400` with the same `target_date` error as 2.4.

### 2.6 Body is not JSON

```bash
curl -i -X POST $BASE/api/courses -H "$JSON" -d 'this is not json'
```

Expected: `400`

```json
{"error": "Request body must be valid JSON"}
```

### 2.7 Body is a JSON list instead of an object

```bash
curl -i -X POST $BASE/api/courses -H "$JSON" -d '[1, 2, 3]'
```

Expected: `400`

```json
{"error": "Request body must be a JSON object"}
```

### 2.8 Course not found – GET

```bash
curl -i $BASE/api/courses/9999
```

Expected: `404 NOT FOUND`

```json
{"error": "Course with id 9999 not found"}
```

### 2.9 Non-numeric id

The route only accepts integers, so Flask never reaches the course lookup.

```bash
curl -i $BASE/api/courses/abc
```

Expected: `404`

```json
{"error": "Resource not found"}
```

### 2.10 Course not found – PUT

```bash
curl -i -X PUT $BASE/api/courses/9999 -H "$JSON" -d '{
  "name": "Ghost",
  "description": "Does not exist",
  "target_date": "2026-12-31",
  "status": "Not Started"
}'
```

Expected: `404`

```json
{"error": "Course with id 9999 not found"}
```

### 2.11 PUT with invalid data on an existing course

The same rules as POST apply to every field you send. Validation runs
**before** the lookup, so a bad body is a 400 even when the course exists.

Invalid status:

```bash
curl -i -X PUT $BASE/api/courses/1 -H "$JSON" -d '{"status": "Done"}'
```

Expected: `400`

```json
{"error": "Invalid status 'Done'. Must be one of: Not Started, In Progress, Completed"}
```

Empty value:

```bash
curl -i -X PUT $BASE/api/courses/1 -H "$JSON" -d '{"name": ""}'
```

Expected: `400`

```json
{"error": "Field(s) cannot be empty: name"}
```

No recognised field at all:

```bash
curl -i -X PUT $BASE/api/courses/1 -H "$JSON" -d '{"colour": "blue"}'
```

Expected: `400`

```json
{"error": "Provide at least one of: name, description, target_date, status"}
```

### 2.12 Course not found – DELETE

```bash
curl -i -X DELETE $BASE/api/courses/9999
```

Expected: `404`

```json
{"error": "Course with id 9999 not found"}
```

### 2.13 Deleting the same course twice

```bash
curl -i -X DELETE $BASE/api/courses/1
curl -i -X DELETE $BASE/api/courses/1
```

Expected: first `200`, second `404`.

### 2.14 Unsupported HTTP method

```bash
curl -i -X PATCH $BASE/api/courses/1 -H "$JSON" -d '{"status": "Completed"}'
```

Expected: `405 METHOD NOT ALLOWED`

```json
{"error": "Method not allowed"}
```

### 2.14b Writing to the statistics URL

Statistics are read-only, so only GET is allowed.

```bash
curl -i -X POST $BASE/api/courses/stats -H "$JSON" -d '{}'
```

Expected: `405 METHOD NOT ALLOWED`

```json
{"error": "Method not allowed"}
```

### 2.15 Unknown URL

```bash
curl -i $BASE/api/nothing-here
```

Expected: `404`

```json
{"error": "Resource not found"}
```

### 2.16 Corrupted data file (file read error)

Stop the server, break the file on purpose, restart, and request the list:

```bash
echo '{not valid json' > courses.json
curl -i $BASE/api/courses
```

Expected: `500 INTERNAL SERVER ERROR`

```json
{"error": "Could not read /path/to/CodeCraftHub/courses.json: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)"}
```

Fix it by deleting the file; the server recreates it empty: `rm courses.json`
